# 文档通路 + Excel 全区配置 —— 方案（待批）

> 需求来自老板：① **文档通路**（上传 / 存储位置 / 关联到客户·车·工单·订单 / 状态阶段 / 检索，并明确权限与保留）；
> ② **能不能用一张 Excel 完成整个 workshop 的配置** —— 下载模板、改、重新上传就更新（parts、campaign、以及任何细节）。

本文件是**方案**，不是实现说明。批准后再按分期动工（与佣金引擎同一套流程）。

---

## 0. 一句话结论

- **文档通路**：能，而且**必须先修存储的隐私问题**（现在 Attachment 存的是**公开 URL**，客户身份证/保险单走这条路等于公开）。
- **Excel 配置**：能，而且比逐页点选更适合你们的场景（一次性把 200 个零件、30 个套餐、几十个促销建好）。
  但要配得上「**先给我看改了什么，再决定要不要应用**」这条硬规矩 —— 否则一次上传就能把整店配置改坏且没人知道。

## 1. 现状盘点（我查过代码，不是估计）

### 已经有的

| 能力 | 在哪 | 状态 |
| --- | --- | --- |
| CSV 导入 | /api/import/customers、/products、/motorcycles + /workshop/import 页 | 能用，但只覆盖 3 类，且**各写一套手工解析** |
| CSV 导出 | /api/export?type=customers\|leads\|products\|bookings | 能用，手工拼字符串 |
| 附件表 | Attachment（relatedType + relatedId + url） | **表是空的**（生产 0 行）→ 可以直接替换，没有迁移负担 |
| 文件存储 | providers/storage/supabase.ts（桶 dz-assets） | put 上传后返回**公开 URL** |
| 工单照片 | ServiceJobPhoto（photoKey + sha256，注释写明「私有对象键，绝不走公共」） | 已按私有思路做过一份 |

### 三个我发现的隐患（本方案会一并修掉）

1. **Attachment 存公开 URL** —— 现在没人用它（0 行），一旦开始用就晚了：客户的身份证、保险单、员工证件都会变成「知道链接就能看」。
2. **CSV 导出会写坏数据**：导出是手工 join 逗号拼的，只有 address 做了逗号替换，**姓名/备注里有逗号或引号就会串列**；以 = + - @ 开头的内容还会被 Excel 当成公式（CSV 注入）。
3. **导入与界面是两套校验**：CSV 导入自己解析、自己判断，同一份数据在界面能过、在导入里可能过不了（或反过来）—— 这正是本项目反复吃过的「同一规则两份实现」。

## 2. Part A：文档通路

### A1. 数据模型（新表 Document，替换 Attachment）

| 字段 | 说明 |
| --- | --- |
| organisationId / branchId | 分行隔离（与工单同一套规则） |
| kind | 文档类型：CUSTOMER_ID / INSURANCE / WARRANTY / INVOICE / QUOTE / PURCHASE_ORDER / SUPPLIER_DOC / STAFF_DOC / PHOTO / OTHER |
| status | 见 A3 的状态机 |
| storageKey | **私有对象键**（不是 URL）—— 访问一律经服务端换取短时签名 |
| fileName / mimeType / sizeBytes / sha256 | 元数据；sha256 用于去重与完整性校验 |
| customerId / motorcycleId / leadId / bookingId / jobId / invoiceId / purchaseOrderId / supplierId | **显式外键**（不用 relatedType 字符串：字符串关联查不了、也不会跟着删改） |
| uploadedById / uploadedAt | 谁传的 |
| verifiedById / verifiedAt / verifyNote | 审核留痕 |
| retainUntil / legalHold / deletedAt | 保留与删除（见 A6） |

### A2. 存储与访问（先修隐私）

- 桶改为**私有**；上传只返回 storageKey。
- 读取：GET /api/documents/[id]/file —— 先校验**身份 + 分行 + 权限**，再返回短时（60 秒）签名 URL 或直接流式转发；**下载也写审计**。
- 限制：类型白名单（pdf/jpg/png/webp/heic/docx/xlsx）、单个上限（建议 20MB）、每组织总量上限（防跑满配额）。
- 照片保持现状（已私有），但并入同一张 Document 表，避免两套路径。

### A3. 状态阶段（一条通用状态机，不按类型分裂）

    UPLOADED → VERIFIED → ARCHIVED
        ↘ REJECTED（可重新上传）

    EXPIRED（到期）/ DELETED（软删，仅 OWNER，可恢复）

含义：**上传 ≠ 有效**。保险单到期要能自动变 EXPIRED 并提醒，客户身份证被审核过才有 VERIFIED —— 这是「文档通路」与「文件柜」的区别。

### A4. 检索

- 客户页 / 车页 / 工单页 / 发票页各有「文件」区块（按上面那组外键自动聚合）。
- 全局 /workshop/documents：按类型、状态、到期时间、客户、车牌筛选；默认视图是**待审核 + 即将到期**（刻意不把它做成又一个报表）。
- 到期提醒走既有 Notification + cron 机制（与 commission-tiers 那个 cron 同一套写法）。

### A5. 权限（复用 RBAC 矩阵 + 分行）

| 动作 | 谁能做 |
| --- | --- |
| 上传 / 查看自己分行的文档 | 具备该模块 edit 权限的员工（默认：机修看工单文档、柜台看客户文档） |
| 审核（VERIFIED / REJECTED） | MANAGER / OWNER（或矩阵里显式授权） |
| 删除（软删） | OWNER（分支级账号不能删 org 级数据） |
| 骑手可见 | 默认**不可见**；发票/保修单这类要开给客户的，走**单独的「对外可见」标记**而不是整表放开 |

### A6. 保留与删除（retention）

- 策略存字段而非代码：Organisation 上的保留期配置（可按类型覆盖，如发票 7 年、工单照片 2 年、客户证件在关系结束后 1 年）。
- 每晚 cron：算出 retainUntil → 到期前 30 天提醒 → 到期后进 ARCHIVED → 宽限期（30 天）→ 硬删（同时删对象存储里的文件）。
- legalHold 为真则**永不自动删**（争议/审计期间）。
- 删除一律先软删 + 审计（谁、何时、为什么）；硬删也要留一条审计行（不含文件内容）。

## 3. Part B：一张 Excel 完成整个 workshop 的配置

### B1. 为什么是 Excel 而不是 CSV

CSV 一个文件只能装一张表，而「整个 workshop 的配置」天然是多张表（零件 + 套餐 + 促销 + 佣金 + 模板…）。
Excel 一个工作簿可以有很多 sheet，还能带下拉、批注、示例行 —— 这正是老板要的**一张表搞定**。
技术选型：exceljs（读写 xlsx）。

### B2. 工作簿长什么样（每个实体一个 sheet）

| Sheet | 能用 Excel 做什么 |
| --- | --- |
| Products（零件/商品） | 建/改：SKU、名称、分类、品牌、成本价、售价、最低库存、条码；**期初库存**也能在这里给 |
| Packages + PackageItems | 建/改套餐及其包含项（服务、零件、数量） |
| Services（服务） | **只能改价格/间隔/是否启用**，不能新建（服务目录由代码定义，见 B6） |
| Campaigns（促销） | 建/改：名称、类型、折扣、起止时间、适用条件 |
| Commission（佣金规则 + 阶梯） | 建/改规则与奖励目标 |
| MessageTemplates | 建/改消息模板文案 |
| Checklists | 建/改检查表与项目 |
| Suppliers | 建/改供应商 |
| Branches / Staff | 分行与员工（员工有权限红线，受限于角色高度规则） |
| Customers / Motorcycles | 批量建档（已有 CSV 导入，合并进来） |

每个 sheet 的第一行是**表头 + 必填标记**，第二行是**示例**，另有一个隐藏 sheet 记**模板版本**。

### B3. 往返流程（这是整个方案的核心）

    ① 下载：点「导出当前配置」→ 得到一个**已经填好现状**的工作簿（不是空模板）
    ② 修改：在 Excel 里改（新增行、改单元格、要删的行在 _action 列写 delete）
    ③ 上传：回到页面选文件 → **服务端只解析与校验，不写库**
    ④ 预览：显示每个 sheet 的「新增 N / 修改 M / 删除 K / 出错 E」，**逐行列出错误与原因**
    ⑤ 确认：点「应用」才写库（按 sheet 一个事务），并写审计（含改了什么的前后值）

**为什么必须这样**：一次上传可能改动几百个价格。没有第 ④ 步，老板只能「上传后祈祷」；有了它，出错的代价从「整店配置被改坏」降到「看一屏预览」。

### B4. 安全规则（写进实现约定，避免以后有人图省事绕过）

1. **稳定键**：每行必须有 SKU / code / 名称这类稳定键；没有键的行只能新增，不能猜要改哪一行。
2. **不进则不删**：**文件里没有的行绝不被删除** —— 删除必须在 _action 列显式写 delete。
   （否则用户拿着旧版本的工作簿上传，会把之后新增的东西全删掉。）
3. **全或无**：一个 sheet 内出错就不应用该 sheet（默认整体中止，不半途改一半）。
4. **上限**：单文件 10MB / 单 sheet 5000 行 / 单次总改动 5000 行（超了让人拆开传）。
5. **审计**：每次导入写 AuditLog（谁、文件 sha256、每个 sheet 的增删改数量、逐行差异）。
6. **权限**：导入是**高危动作**，要求显式权限（默认 OWNER / MANAGER），并受分行隔离约束。
7. **回滚**：至少提供「把导入前的状态再导出一份」（一键下载 before 快照）用于人工比对；自动回滚留到后期评估。

### B5. 校验只有一份实现

把每个实体的校验规则从 Server Action 里抽到 modules/config/validate.ts，**界面表单与 Excel 导入都调它**。
理由：项目已经栽过「同一规则两份实现」的坑（权限矩阵、导航矩阵），而且这里更贵 —— 界面上一行报错 vs 导入里几百行报错。

### B6. 一件必须说清的事：用 Excel 改数据 ≠ 用 Excel 改系统

| 能用 Excel 配 | **不能用** Excel 配 |
| --- | --- |
| 目录与政策数据：零件、价格、套餐、促销、佣金规则、模板、供应商、检查表、客户、车辆 | **服务目录本身**（服务的 key 由代码定义，Excel 只能改它的价格与间隔） |
| | **表结构 / 字段**（那是开发的事，不是配置） |
| | **权限矩阵与角色**（涉及授权红线，必须走界面与被审计的动作） |
| | **历史单据**（发票、工单、台账：只读，不能被导入改写） |

最后一条尤其重要：**导入永远不碰已经发生的业务单据**。否则「改一下 Excel」就能改历史账，那是审计灾难。

## 4. 分期与验收标准

| 期 | 内容 | 验收标准（能做到才算完成） |
| --- | --- | --- |
| **P0** | 存储私有化 + Document 表 + 上传/查看/关联（客户 + 工单）+ 权限 + 审计 | 客户身份证上传后，**未登录/无权限访问该 URL 必须失败**；有权限者在客户页能看到并下载；每次下载有审计 |
| **P1** | 文档扩展（发票、采购单、供应商）+ 状态机（审核/驳回）+ 全局 Documents 页 + 到期提醒 | 保险单到期自动标 EXPIRED 并出现在待办；审核留痕可查 |
| **P2** | **Excel 往返 v1：Products / Packages / Campaigns 三张 sheet** | 导出→改价→上传→预览显示「修改 3 行」→应用后界面价格确实变了；文件里删掉的行**不被删除** |
| **P3** | 扩展到佣金规则、消息模板、检查表、供应商、客户/车辆（合并旧 CSV 导入） | 旧的三个 CSV 导入退役，同一套校验与预览 |
| **P4** | 保留策略与自动清理 + legal hold + 全量导出（数据可携带） | 到期文档自动归档；硬删前有 30 天窗口与提醒 |

## 5. 需要老板拍板的 6 件事

1. **保留期**：发票/工单/客户证件/照片各留多久？（建议：发票与收款 7 年、工单与照片 2 年、客户证件在关系结束后 1 年 —— 若你们有会计或法规要求，以那个为准）
2. **谁能审核文档**：只有 OWNER，还是 MANAGER 也可以？
3. **客户能不能看到自己的文档**：默认我建议**不能**（要开的单独标记），你要不要给 rider 端开「我的保修单/发票」？
4. **上传上限**：单文件 20MB 够吗？（手机拍的 PDF 通常 2-5MB）
5. **Excel 第一期先做哪三张 sheet**：我建议 Products（零件）→ Packages（套餐）→ Campaigns（促销），因为这三样最多、最烦手工录。同意吗？
6. **导入权限**：只有 OWNER，还是 MANAGER 也能导入？（我建议 OWNER + MANAGER，但删除行只允许 OWNER）

## 6. 我不打算做的事（免得以后反复讨论）

- **不做在线表格编辑**（把 Excel 搬到网页里做富编辑器）：Excel 是老板已经会用的工具，硬造一个更差。
- **不做双向同步**（改了网页自动回写 Excel 文件）：那需要一个文件服务与冲突解决，收益远小于复杂度。
- **不让导入碰历史单据**（见 B6）。
- **不做文档的版本历史树**（同一份文件的多版本）：第一版只保留「最新 + 被替换的旧件归档」，真有需要再加。
