## 改动

P4 第三块的最后一件，也是**唯一不可逆**的一件。

### 1. 删除计划**从两个单一事实来源推导**，不手写

一家店在 87 个模型里占了 **80** 个。手写一张"要删哪些表"的清单一定会漂移，
而漏一张表的表现有两种，都比报错更难收拾：

- 删到一半外键报错（还算好的，至少没删成）；
- **"看起来删成功了、其实留下一批孤儿行"** —— 这些行还带着 `organisationId`，
  下次谁按租户查就会看见一家"已经退租但还有数据"的店。

所以新增生成器 `scripts/gen-tenant-purge-plan.ts`，输入是：
- `TENANT_SCOPE`（`src/lib/tenant/scope-map.ts`）—— **哪些模型属于租户**，以及经关系到达租户的路径；
- Prisma **DMMF** —— 模型之间的外键方向，用来定**删除顺序**。

输出 `src/modules/platform/purge-plan.generated.ts`：`PURGE_ORDER`（81 项，先子后父，
最后一项是 `Organisation`）+ `PURGE_WHERE`（每个模型的删除条件：
`column` → `{organisationId}`；`relation` → 沿 scope map 的路径嵌套，如 `Booking` → `{branch:{organisationId}}`）。

生成器**自检**：顺序必须满足每一条外键边，否则直接抛错不写文件；还会列出
"purge 集合之外的模型引用了租户数据"的情况（那种表会挡住删除，需要人工判断）。

### 2. 三道闸门（都在服务层，不靠 UI）

| 闸门 | 为什么 |
|---|---|
| **先停用**（必须是 `SUSPENDED`） | 两步走，避免"顺手删了一家正在营业的店" |
| **原样输入 slug** | 打字确认比勾选框难糊弄 |
| **删除与复核在同一个事务** | 复核发现残留就**整体回滚** —— 宁可"没退成"，也不要"退了一半"（半家店比整家店更难收拾） |

### 3. 墓碑（`TenantTombstone`）

删完之后留下一条**只增不改、不挂外键**的记录：`slug` / `name` / `purgedAt` / 谁删的 / 行数快照。

- **`slug` 永久占用**：`provisionTenant` 会拒绝已退休的句柄。这是**最危险的一类串店**的解法 ——
  否则旧的门口二维码、打印出来的链接、客户收藏的 URL 会全部指向"下一家同名店"。
- **对账**：某个月少了一家店、少了多少行，这里查得到。

### 4. UI：先看清要删什么，再打字确认

`/platform/<slug>` 的退租块只在**停用后**出现，并先展示预演（逐表行数 + 总数），
再要求原样输入 slug。退租成功回租户列表并给出回执（"已退租 X（删除 N 行）"）。

### 5. 顺手修掉一个**真的会误导人**的写法

浏览器冒烟时发现：`purgeTenantAction` 把服务层返回的结果丢掉、**无论成败都 redirect** ——
确认串写错时界面"跳走了、看起来像成功了"，而店铺其实还在。同一个写法在
停用/恢复、授予支持访问的 action 里也有。现在三处都改成**失败要说出来**：
重定向回本页并带 `?err=<原因>`，页面渲染一条红条（列表页与支持页同样能显示）。
（`setTenantStatus` 还顺带补了缺失的 `slug` 隐藏字段 —— 少了它，失败会跳到租户列表，
报错就没人看得见了。）

## 影响

- 平台侧能安全地退掉一家店：**删得干净**（逐模型复核为 0）、**不可误删**（停用 + 打字确认）、
  **留得下账**（墓碑 + 平台审计 + 行数快照）、**句柄不复用**。
- 退租是**唯一不可逆**的平台动作，所以它的测试也按不可逆来写：删完之后拿 scope map
  逐模型数一遍，必须全 0。

**变异测试（四条，都实测会红）**：
- 计划里漏掉一张表（`Attachment`）→ 红 2 条（完整性 + 生成器可复现）。
- 把 `Organisation` 挪到顺序最前 → 红 3 条（拓扑序 + 真删失败）。
- 去掉"必须先停用"这道闸门 → 红 3 条。
- 墓碑不再占用 slug → 红 1 条（"已退休"）。

**踩到的坑（都留在了代码注释里）**：
1. **拓扑方向写反了**：第一版让"父先于子"，而大多数外键指向不在集合里的 `Organisation`，
   于是顺序退化成注册顺序、末尾停在 `StockMovement`。改成 Kahn（"所有引用它的模型都删完才轮到它"）
   并加自检后，末尾正确变成 `User → Customer → Branch → Organisation`。
2. **占位符判断写成了 `"{{ORG}}" in node`** —— `in` 查的是**键**，而占位符是**值**，
   于是永远匹配不上、递归一路走到字符串的每个字符上（栈溢出）。改成按值判断，
   并把解析器提成一个共享函数（原来在两处各抄了一份）。
3. `python3 - <<'PY'` 里用 ASCII 双引号写中文注释 → SyntaxError（今天第二次踩，改用 edit 工具）。
