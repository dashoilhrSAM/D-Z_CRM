## 怎么发现的

PR #57 部署成功后我按惯例去生产上看页面。佣金配置页查到的结果是：

  hasCostCard: false

**卡片根本没渲染。** 原因是生产台账目前 0 行（历史工单都在台账上线前完工），
而我的卡片逻辑是「在台账出现过的窗口里找当前月」—— 没有台账就没有窗口，于是整块不显示。

后果是：**老板打开佣金配置页，看不到任何变化，会以为功能没上线。**

## 这正是我一直在防的那类失败 —— 而这次是我自己造成的

整条佣金线里我反复说过同一个问题（P3 面板空状态、P4 台账为空不能让工资清零）：
**「代码对了」和「用户看得见」是两件事**。测试全绿、部署成功、页面也没报错 ——
而老板看到的是一个和上周完全一样的页面。

## 改法

1. 把**单窗口统计**抽成独立函数 windowStatFor({organisationId, windowKey})：
   有没有台账都要能回答「这个窗口花了多少佣金、占营业额多少」。
   对账报告里的逐窗口统计也改用它 —— **同一条口径只实现一次**；
2. 佣金配置页改为**永远显示**这张卡片；本月没有计提时，明确写出来：
   「本月还没有计提佣金 —— 之后完工的工单会自动计入。台账上线前完工的历史工单仍按旧的人员级口径发放。」
   （后半句很重要：否则老板看着 0 会以为历史工单的佣金丢了）
3. 卡片在营收为 0 时显示「—」而不是 0%（0/0 不是 0%）。

## 验证

- 全量 **59 文件 / 728 测试**通过，tsc 与 eslint 干净；
- 合并部署后我会**再回生产确认那张卡片出现了**（这次不看代码，只看页面）。

## 这一轮的元教训（写给下一次）

**「部署成功」不等于「用户看到东西」。** 我应该在写卡片的那一刻就问一句：
生产上现在有没有台账？—— 这个问题一秒钟就能答（查一行），而我没问。
以后凡是「加一块新的展示」，发布后必须**在真实环境里确认它出现了**，而不是确认代码合并了。
