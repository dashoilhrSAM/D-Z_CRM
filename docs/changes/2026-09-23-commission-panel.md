## 这一期做什么

P3 的表、判定、领取动作都已完成（PR #48 / #49）。这一期把**技师唯一真正会看到的那一屏**做出来：
放在 **/mechanic-app/earnings**（技师看钱的地方）——与工资明细同一页，因为
**技师看「我这个月能拿多少」时不该在两个地方各看一半**。

设计稿 §3.4 要求这一屏展示四件事，缺一件技师都会来问人：

1. **我适用的组合**：名称 + 作用域（单个商品 / 某个服务 / 一个分类 / 全店）+ **配套的基础规则**
   —— 只看「阶梯」看不懂自己在赚什么，必须和「这单本来拿多少」放在一起；
2. **进度**：本窗口 7 / 10 件 + 进度条 + 「再 3 件触发下一档」；
3. **可领取**：档位卡片 + 领取按钮，点完立刻变「已领取 — 随本月结算发放」
   （不能让按钮点了没反应），并即时刷新；
4. **历史**：往期已领（与工资明细同源，避免两处数字）。

另有一句常驻说明：「每月结束时仍未领取的奖励会自动补发，不用担心忘记点」——
把 P3 的过期策略**写在技师看得见的地方**，而不是只写在代码注释里。

## 实现要点

- 组件是客户端组件（领取是交互），数据来自服务端的 tierPanelFor()；
- 面板数据里的**日期在服务端转成字符串**再传：跨 RSC 边界传 Date 容易踩时区与序列化的坑，
  而这一屏显示的是「哪一期」，不是精确时刻；
- 文案 19 个键，en / zh / ms 三语；
- 语言 provider 在**根 layout** 已挂（与其它技师组件同一套 useLang()），无需额外接线。
