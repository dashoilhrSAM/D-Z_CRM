## 老板的反馈

> 「我在 items 里删了一行，但它没检测到改动。请交叉检查全部。」

查完的结论：**检测逻辑是好的，问题出在「删除」这件事没被讲清楚**。

## 交叉检查的结果（对生产数据，逐张表）

**A. 在 _action 列写 delete**（正确做法）

    7 张表 ✓ 正确检测为删除（含组合键的套餐明细）
    服务项目 Service Types ✗ 0 条 + 报错 1 行 —— **故意不让删**（服务目录由代码定义）

**B. 在 Excel 里把整行删掉**

    8 张表全部「没有删除」✓ —— 这是**按设计**的

## 为什么 B 是故意的（这条不能改）

**文件里没有的行永不删除** —— 这是本项目最强的一条安全规则。

原因：文件可能只覆盖一部分（你只勾了几张表下载、或者某些行本来就不会被导出）。
如果「缺了就删」，那么一份残缺的文件就能**清空整张表**，而且没有任何办法撤销。

所以删除只能显式表达：**在那行的第一列 _action 写 delete**。

## 修的是「看不见」，不是「行为」

| 改动 | 为什么 |
| --- | --- |
| **_action 列挪到第一列** | 它原本在最右边 —— 老板删了行却「什么都没发生」，那一列太容易被滑过去（这是真实反馈） |
| **界面显示「文件里 X 行 · 库里 Y 行」** | 数字摆在眼前，不用猜 |
| **少了行时给一条橙色提示** | 直接写明：N 行不在这个文件里；它们**不会被删除**，要删请在该行**第一列 _action** 写 delete |
| **「不允许删」的报错说人话** | 原来只有一句 rows in this sheet cannot be deleted on their own；现在会说哪张表、为什么，并提示「删行要保留键的列」 |
| **列对照 sheet 的说明补强** | 原来就有「留空=新增/修改; delete=删除」，现在补上「文件里没有的行永远不会被删除」 |

## 固化下来（免得以后再坏）

- **新增 4 条测试**：每张表的 delete 检测（服务目录必须报错）、缺行绝不删除、
  「库里的行数」与「现状行数」必须一致（否则界面会报出假的「少了几行」）、_action 必须在第一列
- **新增常驻检查脚本 scripts/check-bulk-deletes.ts**：对生产数据把 A/B 两种行为逐张表跑一遍
- 全量 **64 文件 / 794 测试**通过；tsc / eslint 干净

## 操作说明（给老板）

**要删一行**：在该行**第一列**写 delete（**其它列保持原样**，尤其是作为键的那一列）；
**只是把那行删掉**：等于「这次没提到」，库里那行**原样不动**。
