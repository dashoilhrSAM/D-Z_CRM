## 最后一张表，也是车辆表的前提

客户表是**车辆表的前提**（车辆要挂车主）和**退役旧 CSV 导入的前提**。
列名沿用老板模板 07_客户名单：**姓名 / 手机 / 邮箱 / 地址 / 标签 / 备注**。

## 判重规则（动手前先给老板看过，四条全部确认）

| 规则 | 行为 |
| --- | --- |
| **键 = 手机号（归一化后）** | 一个手机号 = 一个客户；与车辆表找车主用的是同一把尺 |
| 没手机号的行 | **报错**（不建）—— 没有手机号就没法可靠认人 |
| 手机号在库里 → **修改** | 文件里写了值的字段更新，留空＝不动（改动在预览里逐行显示旧值→新值） |
| 手机号不在库里 → **新增** | 整行新建 |
| 文件里两行同一手机号 | 报错（引擎已有） |
| 文件里没有的行 | **绝不删除** |
| **邮箱不做键** | 夫妻/公司共用一个邮箱是现实的，用它做键会误并 |

额外一条（老板确认）：**邮箱撞上另一个客户 → 报错，不自动合并** ——
自动合并会在「换号写错一次」时并错人，而报错只是让人看一眼。

**手机号只归一化用于比对，存进去的仍是你写的写法**（与车牌同一条处理）。

## 一个顺序上的关键点

**客户先处理，然后是车辆**（其余按原顺序）。且新建客户后**立刻更新手机号映射** ——
这样**同一份工作簿里可以「先建客户、再挂他的车」**：正是新店开张时最自然的用法。

（否则车辆行的车主查找用的是导入前的地图，找不到刚建出来的客户。）

## 一个差点漏掉的细节

**没有手机号的客户不导出** —— 手机号是键，这种客户导出来也无法被识别，
会变成一行错误并**把整份文件挡住**（一行有错整份不写）。与服务目录里「没有 code 的行不导出」同一条处理。
