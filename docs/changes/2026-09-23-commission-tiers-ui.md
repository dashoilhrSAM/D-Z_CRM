## 为什么这一块不能省

做完表、判定、领取、面板之后，我核对生产数据发现：**CommissionTierSet 与 CommissionRule 都是 0 行**。

也就是说整套东西**做好了但没人用得上** —— 老板没有任何界面能建一个「机油买十送二」，
只能改数据库或跑脚本，于是技师面板永远显示「还没有给你设定奖励目标」。

这类「功能做完了但用户用不了」最容易骗过自己：PR 一条条绿、测试 707 条全过、页面也上线了、
截图也对 —— **而界面里无处可点**。判据从来不是「能不能跑」，而是「老板能不能自己完成这一件事」。

## 做了什么

1. **服务端动作 src/actions/commission-tiers.ts**：列表（含选择器要用的目录：商品/服务/分类）、
   新建或更新（连档位一起写）、停用/启用。三道门与佣金规则一致：
   **矩阵权限 TECHNICIANS/edit** + **入参校验** + **资金类写入留审计**；
2. **管理界面**（接在 /workshop/commission 下方，与基础规则同一页）：
   - 适用范围：全店 / 单个商品 / 某个服务 / 一个分类（选完才出现对应对象选择器）；
   - 计件方式：按件数 / 按账单行数；
   - **奖励形态三选一，每种都带人话说明 + 算式示例**（设计稿 §3.1 的硬要求：
     「10 units → RM50 once」「10 units × RM2 = RM20」「2 free units × RM5 = RM10」）；
   - 档位可加多档（满 10 → RM50、满 20 → RM120），每档都要门槛与奖励；
   - 追溯开关只在「每件额外加」这种形态下出现；
   - 生效日期可选；停用后不再计入面板，但**历史领取记录保留**。

## 几个刻意的取舍

- **档位整体替换而不是逐条 diff**：组合的档位是一组定义，逐条改会留下「删了半截」的中间态；
- **校验在服务端**，客户端只为体验服务。已拦：名称为空、范围与对象不匹配（全店不该指定对象、
  指定对象却没选）、门槛 ≤ 0、奖励 ≤ 0、**两档门槛重复**、商品/服务已不存在；
- 停用而不是删除：历史台账与领取记录指向它，删掉会让过去的账说不清。
