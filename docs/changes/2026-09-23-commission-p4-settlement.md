## 这一期关掉的口子

settlePayouts 原本收的是**调用方算好的 commissionSen**。页面算得对就没事，
但「钱」这件事不该建立在「调用方算得对」之上 —— 台账才是唯一真相
（设计稿 §4.5 不变量 1：Σ ledger(窗口, 人) == StaffPayout.commissionSen）。

这一期把发薪时的佣金改成**从台账推导**，并落实设计稿 §4.4 的两条规矩。

## 三条硬规矩（都有测试钉住）

1. **按 earnedAt（计提时刻）取数**：8 月的工单 9 月 5 日才完工，钱发在**9 月**这个周期，
   并标出它是跨期调整（lateSen / lateWindowKeys）。按窗口键匹配会让这类单永远发不出去。
2. **没有台账 → 保留旧口径，绝不当成 0**：P2 之前的历史工单根本没有台账行，
   把「没有台账」当 0 等于**一键清零历史工资** —— 这是本项目最忌讳的那类静默失败。
   这时 source = LEGACY，并在审计里写明「legacy figure kept (not zeroed)」。
3. **期间锁**：StaffPayout.status = PAID 之后金额**冻结**，重跑 settle 只计数不改写
   （否则历史工资单与银行流水对不上）。

另外：台账数与提交数不一致时**差额留痕**（driftSen 进审计），让「这个月数字怎么变了」有据可查，
而不是悄悄改掉。

## 符号规则（四种 kind）

BASE + TIER_BONUS + ADJUSTMENT − REVERSAL。冲正是**减号** —— 这一条单独有测试，
因为把冲正当加号写反了，只会让某个月的工资悄悄多一截，没有任何报错。
