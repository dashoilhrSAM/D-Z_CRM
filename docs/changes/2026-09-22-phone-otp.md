## 改动

Rider（顾客）现在可以用**手机短信验证码**注册与登录，不再只有密码一条路。

链路：页面 → Server Action（限流 + 预写审计）→ Supabase 生成验证码 →
**Send SMS Hook**（本仓库 `/api/hooks/send-sms`）→ SMS provider 真发 → 验码 → 绑定/认领 Customer → 注入 claims。

| 位置 | 内容 |
| --- | --- |
| `src/app/api/hooks/send-sms/route.ts` | Supabase Send SMS Hook 落点（Vercel 路由，非 Edge Function） |
| `src/lib/api-auth.ts` | `requireSmsHookSecret()`：恒定时间比较 + 缺密钥 503（fail-closed） |
| `src/middleware.ts` | `API_PUBLIC` 增加 `/api/hooks`（靠 Bearer secret，不是裸的） |
| `src/providers/sms/{mock-sms,twilio}.ts` | SMS provider 实现；**mock 在 production 主动失败**，不许"发送成功但没人收到" |
| `src/lib/otp.ts` | 号段白名单 / 频率判定 / 短信文案 / 脱敏 / E.164 归一化（纯函数，可单测） |
| `src/actions/auth-supabase.ts` | `requestRiderPhoneOtp` / `verifyRiderPhoneOtp` / `completeRiderPhoneSignup` |
| `src/app/rider/{login,signup}/page.tsx` | 登录加"短信验证码"tab；注册加"验证码注册"方式（无需密码） |
| `prisma`（双 schema + 迁移） | 新表 `OtpAttempt`：发送审计 + 限流数据源 |

顺带修掉一个**现网身份 bug**：`src/lib/phone.ts` 的 `combinePhone()` 不处理马来本地号的前导 0 ——
`combinePhone("+60","013-125 2832")` 得到 `+600131252832`（多一位、非法 E.164）。
症状不报错，而是"这个号码找不到任何客户" + Supabase 拒绝建号。修复前实测输出：
`{"input":"013-125 2832","combinePhone":"+600131252832","matchesStored":false}`。

## 影响

- **必须先开 Phone provider**：实测本项目 Supabase 项目（`dukbfgqbrprivnzcsrlh`）`external.phone=false`，
  在此之前 `signInWithOtp({phone})` 必然失败、hook 永远不会被调用。仪表盘还需配 Test OTP 与 Send SMS hook。
- 新增 env：`SMS_HOOK_SECRET`、`TWILIO_ACCOUNT_SID`、`TWILIO_AUTH_TOKEN`、`TWILIO_FROM`、
  `OTP_EXPIRE_MINUTES`（默认 5，须与仪表盘 SMS OTP Expiry 一致）、`OTP_ALLOWED_COUNTRY_CODES`（默认 `+60`）。
- 新表 `OtpAttempt` 属附加变更，构建期 schema 同步会自动应用到生产（不触发 DROP/TRUNCATE 拦截）。
  本地已对 `dev.db` 与 `e2e.db` 各跑一次 `prisma migrate deploy`。
- 老客认领：`Customer.authId` 为空的历史客户（seed 那批）验证手机号后第一次有了登录方式。
- 已有**邮箱账号**的客户不能用 OTP 登录（Supabase 会新建身份而不是合并）——明确拒绝并引导用邮箱，不做静默合并。
- 密码通道保持可用，未删除任何现有登录方式。

## 交接说明

验证：`pnpm exec vitest run` 全绿（41 文件 / 557 测试，含 9 条真打 hook 路由的集成断言），
`pnpm exec tsc --noEmit` 无错，eslint 无新增错误。

**尚未验证**（需要先做仪表盘步骤）：真实短信到达、Supabase hook 回调、Test OTP 全链路。

上线步骤（按顺序）：
1. Authentication → Providers → **Phone 打开**；SMS OTP Expiry 设 300s（默认 60s 对马来西亚到达时延偏紧）；
   Test phone numbers 配一个测试号（零成本，且不触发 hook）。
2. Authentication → Hooks → **Send SMS**：URL = `https://<domain>/api/hooks/send-sms`，
   scheme = Bearer，secret 与 `SMS_HOOK_SECRET` 一致。
3. Vercel 配 `SMS_HOOK_SECRET` + Twilio 三项（未配 Twilio 时走 mock：本地可测，生产会显式失败）。
4. 用测试号验证登录/注册两条通道，确认 `OtpAttempt` 行从 REQUESTED → SENT、`verifiedAt` 有值。
5. 之后再单独做 CAPTCHA（需要 widget + captchaToken 透传，不是"开个面板开关"）。
