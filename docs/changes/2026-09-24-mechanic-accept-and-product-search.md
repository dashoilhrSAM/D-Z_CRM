## ① 机修「点了 accept order，退出后还是 accept order」

### 根因

卡片上写的是「接单（WAITING → IN_PROGRESS）」，但 `transitionJob` 后面有**两道门禁**：

| 门禁 | 要求 |
| --- | --- |
| SOP-001 | 开工前必须拍齐 **5 张**服务前照片 |
| QUOT-001 | 有报价的工单，报价必须**客户已确认** |

新派下来的工单照片是 0 张 → **每次点接单都会失败** ✗ → 失败后被弹去拍照页 →
退出来工单仍是 WAITING → 卡片**又一次显示 Accept order**。看起来像「接了但没接上」。

### 改法（不废掉那两条规矩）

1. **卡片改成说人话**：照片不满 5 张 → 显示「拍照 3/5 — 开工前先拍齐」并点进拍照页；
   照片齐了但报价没确认 → 显示「等客户确认报价」；两道都过了才显示真正的接单按钮。
2. **拍齐最后一张 = 接单完成**：照片接口在存好第 5 张后直接把工单推进 `IN_PROGRESS`
   （报价门禁仍由 service 把关：过不了就静静留待，卡片上写明在等客户）。
   于是「接单 → 拍照 → 开工」成为一条路，不再需要来回点两次。

判定逻辑抽成纯函数 `src/lib/job-start-state.ts`，因为这类「按钮点了没反应」的 bug
只有把规则写出来才防得住 —— 照片优先于报价、非 WAITING 状态一律不显示接单，都有测试。

## ② 产品页加搜索

按 **名称 / SKU / 品牌 / 分类 / 原厂编号** 搜，大小写不敏感，多个词**全部命中**才算匹配
（搜 oil filter 不会把只含 oil 的也带出来）。显示「显示 N / 共 M」并可一键清除。

过滤规则同样抽成纯函数 `src/lib/product-search.ts` —— 搜索最容易出的 bug 不是搜不到，
而是**空搜索把整张表搜没了**（界面看起来像没有零件）。测试里专门钉住：空搜索返回全部、
真搜不到必须是 0 条。
