## 为什么先还债再写验收

要给工作台写生产验收脚本，第一件事就撞上了一个问题：**「现状行」的构造只存在于 Server Action 里**，
脚本用不到。如果在脚本里再写一份，就等于**复制了那份最容易出错、且已经出过两次事故的逻辑**。

差异计算是拿「文件里的值」对「现状里的值」。现状行少一个字段，**每个有那个字段的行都会被误报成有改动** ——
而假差异比不预览更糟：老板会以为要改的比实际多，然后批准一堆其实没变、他也没细看的行。

所以先把 buildExistingRows() 与 sheetColumns() 抽到 **src/modules/bulk/existing.ts**，
界面、验收脚本、以后的测试**共用同一份**。

## 常驻的生产验收脚本

scripts/verify-bulk-roundtrip.ts —— 对生产跑三件事：

1. **全量往返**：导出 → 解析 → 差异计算，**逐张表读数字**（读入几行、现状几行、改动几条），要求全部零改动
2. **选择性下载**：只勾 3 张 → 文件里声明的就是这 3 张，且**其余 5 张在文件里确实不存在**
   （＝「这次不涉及」，而不是「这张表是空的」——这一条正是 P1 的安全核心）
3. **模板模式**：只有表头，数据行必须是 0

**为什么必须逐张读数字**：只报一个总数时，「某张表根本没被读进来」和「这张表没有变化」
在输出里长得一模一样。这是本项目已经踩过的坑。

用法写在她自己的文件头注释里（连接串从 .env 的 DST_DATABASE_URL 取，不打印任何机密）。

## 一个操作上的注意

脚本要打生产库，而本地 Prisma client 是 sqlite 的 —— 必须先
prisma generate --schema prisma/schema.pg.prisma，跑完**立刻** prisma generate 切回来。
两条命令绑在一起执行，避免忘掉（忘掉的症状是本地 tsc/测试全乱，看起来像代码坏了）。
