## 背景

老板还没拿到 WhatsApp API key。但现在界面上到处都是「发送 / 群发 / 自动化」按钮 ——
点了会**成功**、消息表里也有**记录**、状态还显示**已发送** ✗，**客户手机上什么都不会收到** ✗。

这正是这类系统最该杜绝的「看起来发了其实没发」。

## 做法：自动判断，不写死一句说明

如果只写一句「目前未配置 WhatsApp」的静态文案 ✗，等 key 配好之后它会变成**错的** ✗。
所以说明条**读环境变量自己判断** ✓：

- 配齐 → **不渲染任何东西**（自动消失 ✓，不需要谁记得回来删 ✓）
- 没配 → 显示说明 + **列出还缺哪个变量** ✓

判定比 provider 的选择更严格一点：src/providers/index.ts 只看 WHATSAPP_API_TOKEN，
而真正发消息还需要 WHATSAPP_PHONE_ID —— **只配一半会「选成真通道、发送时才发现缺 phone id」** ✗。
所以这里两样都齐了才算 live ✓。

顺带区分了一件事：**送达回执**（已读/送达状态）需要另外两个变量，
它不影响发送，但没配就收不到「消息到底送到没」—— 在说明里单独提一句 ✓。

## 放在哪

| 页面 | 为什么 |
| --- | --- |
| /workshop/automations | 自动化规则会发消息 |
| /workshop/messaging/templates | 模板是「发给谁看」的入口 |
| /workshop/marketing | 营销群发 |

## 测试（5 条）

- 两样都配齐 → live
- **什么都没配 → 不是 live，且列出缺的两个**
- **只配 token → 仍然不是 live**（这正是「选成真通道但发送失败」的情况）
- 空字符串等于没配（env 里常见）
- 送达回执是另一件事
