## 老板的决定

> 「旧 CSV 导入退役（客户 / 零件 / 车辆那三个老入口）—— 把 bulk import 换去这里」

## 为什么该退

不是因为它不安全（三个 API 路由都有 requireStaff() 门禁），而是**规则两份实现**：

| | 旧 CSV 导入 | 批量配置工作簿 |
| --- | --- | --- |
| 客户判重 | 自己一套 | 归一化手机号 |
| 车辆 | 自己一套 | 归一化车牌 + 类型校验 |
| 零件 | 自己一套 | 按 SKU |
| 删除 | 直接生效 | 显式 _action + 逐条批准 |
| 审计 | 无 | AuditLog + 导入会话历史 |

同一份数据走两条路会得到不同结果 —— 而「同一规则两份实现」是这个项目已经栽过几次的坑。

## 做了什么

| 动作 | 对象 |
| --- | --- |
| **删除** | src/app/api/import/{customers,products,motorcycles}/route.ts |
| **改成重定向** | src/app/workshop/import/page.tsx → redirect("/workshop/setup")。保留重定向而不是 404：老板可能存着旧链接、说明书里也可能印着 |
| **删除导航项** | nav-registry 里的「CSV Import」。批量配置本来就有自己的入口，留着会变成两个入口指向同一件事的两个版本 |
| **改指向** | 客户页的「导入 CSV」按钮、设置页的链接、三个截图/教程脚本 |
| **清理 i18n** | 删掉 3 个不再使用的键，加 1 条新的说明文案 |

## 守卫（防止无意复活）

新增 tests/legacy-import-retired.test.ts，5 条：

1. 三个 API 路由**必须不存在**
2. 旧页面必须是**重定向**（不能删掉变成 404，也不能改回实现）
3. 导航里不许再有指向旧路由的入口
4. **反向**：导航里必须有新入口（退役不能把入口也撤没了）
5. **全仓库扫描**（src / scripts / e2e）：除重定向页自己，任何文件不许再链旧路由

第 5 条是**验证过能失败**的：故意塞回一个链接，它立刻报出文件名；还原后通过。
（本轮它实际抓出 5 处遗留引用：3 个截图/教程脚本 + 客户页按钮 + 设置页链接。）

全量 **65 文件 / 807 测试**通过；tsc / eslint 干净。
