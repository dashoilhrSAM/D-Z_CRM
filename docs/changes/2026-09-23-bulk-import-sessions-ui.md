## 这一期把「存下来」变成「用得上」

上一期做了会话表与状态机（服务端那一半）。这一期让界面真的接上它：

- **打开页面自动接上**上次没审完的那一份（顶部一行「接着上次没审完的那一份（上传于 …）」）
- 审核台里的每个决定**自动存回服务器**（600ms 合并一次，不是每次按键都打一次请求），
  顶部显示**已保存于 …** —— 老板要能确信「我批的这些没丢」
- **已应用/已取消的会话打开时是只读的**：终态不许再改决定，否则历史就成了假的
- **取消这次导入**：什么都不写
- **导出变更清单**（CSV，给会计/老板看的那种）—— 只含已批准的行，带 旧值 → 新值
- **导入历史**：谁、什么时候、哪个文件、几条、批了多少、这次应用的结果（+n / ~n / -n），点「打开」回看逐条

## 一处刻意的实现选择

草稿会话**在服务端读**（page.tsx 里 await 一次），而不是客户端挂载后用 effect 去拉。
原因有两个：一是 React 的 setState-in-effect 规则说得对（挂载时同步 setState 会引起连锁渲染）；
二是这样页面**不会先闪一下空内容再填上**。

## 一个契约上的收紧（顺手做对）

「就地修改」传回服务器的明确是**原始输入**（金额 RM、日期 YYYY-MM-DD 字符串），
服务端解析（cellToValue）并复验。类型上现在写死了这一点（edits: Record<string, string>），
而不是含糊的 unknown —— 这条边界混淆过一次，代价是金额差 100 倍。

## 验证

tsc / eslint 干净；全量 **64 文件 / 790 测试**通过。
**生产验收方式**（合并后做）：上传一份改过的文件 → 批几条 → **关掉页面** → 重新打开确认接上 →
再应用 → 回数据库核对，并在历史里看到这次导入。
