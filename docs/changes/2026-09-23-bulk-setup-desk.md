## 老板要的那件事：从「给你看」变成「让你管」

原话：「有没有一个界面能管理所有这些 Excel 上传下载 —— 我能挑要下载哪几部分，也可以全部；
上传后能看到这次的改动是什么，并且能**逐条 拒绝 / 批准 / 修改**，把录入管起来」。
方案见 docs/BULK_SETUP_DESK_PLAN.md（PR #75）。这一期做 **P1 + P2**。

## P1：选择性下载

- 页面上**勾选要下载哪几张 sheet**（默认全选），另有「只要模板」（表头 + 列对照，不带数据）
- 工作簿的隐藏元数据里写入 **这次包含哪些 sheet**
- 导入时**只处理文件里有的部分** —— 不在清单里的 sheet 是「**这次不涉及**」，不是「这张表是空的」

这一条是整期最关键的安全点：否则你只想改零件、传一份只含零件的文件，
系统会把套餐/车辆/客户当成**全空**（那正是「文件里没有的行绝不删除」要防的事，只是粗一个量级）。

## P2：改动审核台

上传 → 逐张 sheet 分组 → 每行显示动作标签与**字段级旧值→新值** → 每行可以：

- **批准** / **拒绝**（再点一次取消）
- **就地修改**：直接改字段（枚举列是下拉、金额按 RM 填、日期按 YYYY-MM-DD）
  —— 输入框**留空 = 不动**，空白处的占位文字显示库里现在的值（与 Excel 端同一条语义）
- 批量：**批准所有没出错的** / **全部拒绝**
- **出差错的行不能被批准**（要么改对、要么拒绝）

应用时**只写你批准的行**，并给逐行回执。

## 服务端做的两件把关（老板确认的 6 条决定里最硬的两条）

1. **复验**：界面改过的值、以及客户端传回的整个计划，都要重新过一遍列定义
   —— 被篡改的请求不该能绕开枚举白名单或把金额写成文字。
   （技术上有一处必须分清：**计划里的值已经是归一化形态**（分/Date/规范枚举），
   而**界面传回的编辑是原始输入**（RM、YYYY-MM-DD）——后者要解析、前者只做类型复验。
   混淆过一次，测试立刻抓到：9999 分被当成 9999 元。）
2. **预览过期检测**：写入前对着**当前数据库**逐字段比对你预览时看到的旧值；
   不一致说明别人在这期间改过同一条 → **拒绝这一行并说明**，而不是把别人的改动盖掉。
