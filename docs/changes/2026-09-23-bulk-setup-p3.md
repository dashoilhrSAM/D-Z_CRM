docs/setup-templates/06_供应商名单.xlsx 与 03_服务项目.xlsx —— 列名直接沿用它们（与 P2 同一做法）。

| Sheet | 范围 | 内容 |
| --- | --- | --- |
| **供应商 Suppliers** | 组织级 | 名称 / 联系人 / 电话 / 邮箱 / 地址 / 交期(天) |
| **服务项目 Service Types** | 组织级 | 代码 / 服务名称 / 分类 / 工时(分钟) / 标准价 / 启用 |

供应商这张表解决了一个真实的不便：零件表里的「供应商」列**必须写已存在的供应商名字**（未知的会报错，
这是刻意的），所以以前要先在界面里一家家建。现在可以在同一份工作簿里先把供应商写好。

## 服务项目这张表：**只改，不建、不删**

服务目录是**代码定义**的（src/lib/service-catalog.ts 同步进库，带稳定 code），柜台按它出单。
所以这一期给它加了一条新规则：

- **不能新建**：凭空造一个 code 会得到一个「数据库里有、柜台看不到」的服务 —— 那种东西最难查。
  文件里出现未知 code → 明确报错「This sheet only edits rows that already exist」。
- **不能删除**：同理，删掉会让柜台上的服务消失。
- **能改**：价格、工时、分类、名称、是否启用 —— 这些正是常调的。

键用的是 **code**（不是名称）：改名不该变成「新建一项」。

## 机制上的一个小改动

SheetDef 新增 **createAllowed**（默认 true）。它是「这张表能不能新建行」的显式声明 ——
把「服务目录不许新建」这条业务规则放进数据定义里，而不是散在 apply 的分支里靠记性。

## 这一期**故意没做**的（以及为什么）

| 没做 | 原因 |
| --- | --- |
| **员工名单** | 员工涉及身份（邮箱/账号）与角色权限 —— 角色有专用界面与红线校验（不能改自己角色、分行级不能授 org 级角色）。放进 Excel 会让这些红线容易绕过，收益不抵风险 |
| **客户 / 车辆名单** | 这两张是**退役旧 CSV 导入**的前提，但客户导入有「按电话/邮箱判重」的语义，必须先把那套规则抽出来共用，否则会造重复客户 —— 那是独立的一块工作，不能顺手做 |
| **消息模板 / 佣金规则** | 模板是长文本、佣金规则结构复杂（按服务/零件的覆盖 + 阶梯），摊平成表格反而更难核对 |

所以：**旧的三个 CSV 导入这一期不退役**（客户/车辆还只能走它）。等客户/车辆表做完再一起收。
